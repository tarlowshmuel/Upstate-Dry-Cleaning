## Problem
The Dockerfile build fails at step `[builder 10/13] RUN pnpm install --frozen-lockfile --filter @workspace/api-server... --filter @workspace/db... --filter @workspace/api-zod...` with exit code 1. The build log shows:
```
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild@0.27.3
Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.
```
The SNAPSHOT_CODE stage succeeds, but BUILD_IMAGE fails. All 168 packages download successfully, but pnpm then exits with code 1 because esbuild's postinstall script is blocked. This same error occurs on the latest HEAD commit (deployment f0835c75).

## Diagnosis
Starting with pnpm v9.12, dependency lifecycle scripts (postinstall, preinstall, etc.) are blocked by default for security. The project uses `pnpm@11.3.0` (declared in the `packageManager` field of `package.json`), which enforces this policy. esbuild relies on a postinstall script to download its platform-specific native binary — without it, the install step fails. The `.npmrc` file currently contains:
```
auto-install-peers=false
strict-peer-dependencies=false
```
It does not include any configuration to allow dependency build scripts. There is also no `.pnpm-approve-builds` file or `pnpm.onlyBuiltDependencies` field in `package.json`.

## Fix
1. **File:** `.npmrc` (repo root)
2. **Current content:**
```
auto-install-peers=false
strict-peer-dependencies=false
```
3. **Replacement content:**
```
auto-install-peers=false
strict-peer-dependencies=false
onlyBuiltDependencies=*
```
4. **Why:** Adding `onlyBuiltDependencies=*` tells pnpm to allow all dependency build scripts to run, which permits esbuild's postinstall script to execute and download its platform-specific binary. This is the simplest fix and does not require regenerating the lockfile.
